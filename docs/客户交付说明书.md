# Smart Eval 高校处级干部民主测评系统

## 1. 文档说明

本文档用于向客户介绍 Smart Eval 高校处级干部民主测评系统当前版本的功能范围、技术架构、数据模型、部署方式和使用边界。

本文档以当前项目源码、配置文件、数据库迁移脚本及前端页面为依据；“已实现功能”指当前版本代码中已经具备的功能，“版本边界”用于说明当前版本暂未提供的能力。

## 2. 项目概述

Smart Eval 是面向高校处级干部民主测评场景的 Web 系统，支持管理员统一维护测评基础数据、生成测评账号并查看测评结果，同时为测评用户提供手机端登录和在线测评入口。

系统包含两个业务角色：

| 角色 | 使用端 | 主要职责 |
| --- | --- | --- |
| 管理员 | 管理员后台（桌面端） | 管理部门、被测评人员、测评用户和管理员账号，查看测评结果 |
| 测评用户 | 移动端 | 登录后对所属部门的被测评人员进行等级评价并提交 |

## 3. 功能清单

### 3.1 管理员登录与工作台

- 管理员独立登录入口：`/admin/login`。
- 使用管理员用户名和密码登录。
- 登录成功后进入管理员工作台。
- 工作台展示部门总数、被测评人员数、测评用户数、已提交测评用户数和未提交测评用户数。
- 支持退出登录，清除当前浏览器保存的认证令牌。

### 3.2 部门管理

- 部门列表分页查询。
- 按部门名称进行模糊筛选。
- 新增部门，维护部门名称和排序值。
- 编辑部门名称及排序值。
- 删除部门。
- 部门名称唯一；存在被测评人员、测评用户或测评记录关联数据时，系统阻止删除并返回业务提示。

### 3.3 被测评人员管理

- 被测评人员列表分页查询。
- 按所属部门、姓名和启用状态筛选。
- 新增被测评人员，维护姓名、所属部门和启用状态。
- 编辑被测评人员信息。
- 删除被测评人员；存在评价记录时，系统阻止物理删除。
- 单独切换启用/禁用状态。
- 移动端只展示当前测评用户所属部门中处于启用状态的被测评人员。

### 3.4 测评用户管理

- 按部门批量随机生成测评用户账号。
- 单次生成数量限制为 1 至 500 个。
- 自动生成唯一用户名和随机密码，并绑定到指定部门。
- 测评用户列表支持按部门、启用状态和提交状态筛选。
- 查看账号、初始密码、所属部门、启用状态、是否已提交及提交时间。
- 管理员可重置测评用户密码，系统返回新生成的明文密码。
- 管理员可启用或禁用测评用户账号。
- 支持根据当前筛选条件生成账号打印页面，页面以 HTML 形式打开，可直接使用浏览器打印。

### 3.5 管理员账号管理

- 支持多个管理员账号。
- 管理员列表分页查询。
- 新增管理员账号，维护用户名、密码和显示名称。
- 编辑管理员显示名称。
- 启用或禁用管理员账号。
- 重置管理员密码。
- 管理员用户名唯一。
- 系统禁止禁用最后一个处于启用状态的管理员。
- 管理员密码以 BCrypt 哈希形式保存，不以明文保存。

### 3.6 移动端测评

- 移动端登录入口：`/mobile/login`。
- 测评用户使用管理员分配的账号和密码登录。
- 登录后只加载当前账号所属部门的启用状态被测评人员。
- 对每名被测评人员选择一个固定测评等级：优秀、称职、基本称职、不称职。
- 支持在提交前查看已完成评分数量，并返回修改评分。
- 必须完成全部待测评人员的评分后才能提交。
- 提交前进入确认页面，明确提示提交后不能再次修改。
- 提交成功后进入完成页面，并锁定该测评用户的提交状态。
- 已提交的测评用户不能重复提交。

### 3.7 测评结果

#### 结果汇总

- 按被测评人员展示测评结果汇总。
- 展示优秀、称职、基本称职、不称职票数及总票数。
- 支持按部门和被测评人员姓名筛选。

#### 评价明细

- 展示测评用户账号、测评用户所属部门、被测评人员、评价等级、评价标签和提交时间。
- 支持按部门、被测评人员、测评用户和评价等级筛选。
- 当前版本评价记录保留 `comment1`、`comment2` 字段，可用于扩展备注信息；移动端首版不要求填写备注。

### 3.8 统一接口响应与异常提示

- 前端通过统一请求封装访问后端 API。
- API 返回统一的成功标识、数据、消息和校验错误结构。
- 后端对未登录、无权限、参数校验失败和业务规则冲突返回对应错误信息。
- 前端在表格、表单和操作按钮中提供加载状态及成功/失败提示。

## 4. 业务规则

### 4.1 测评等级

| 枚举值 | 页面显示 |
| --- | --- |
| `EXCELLENT` | 优秀 |
| `COMPETENT` | 称职 |
| `BASIC_COMPETENT` | 基本称职 |
| `INCOMPETENT` | 不称职 |

### 4.2 权限隔离

- 管理员令牌只能访问 `/api/admin/**` 接口。
- 测评用户令牌只能访问 `/api/mobile/**` 接口。
- 管理员可查看实名评价明细。
- 测评用户只能提交自己的评价结果，不能访问管理员数据。

### 4.3 提交约束

- 提交内容必须覆盖当前测评用户所属部门的全部启用被测评人员。
- 提交内容不能包含其他部门或已禁用的被测评人员。
- 每个测评用户对每名被测评人员最多保存一条评价记录。
- 提交操作在一个数据库事务中写入评价记录并更新测评用户提交状态。

## 5. 技术栈清单

### 5.1 总体架构

- 前后端分离的单页 Web 应用。
- 后端提供 REST API，也可以统一托管前端构建后的静态资源。
- PostgreSQL 负责业务数据持久化。
- Docker Compose 提供本地 PostgreSQL 16 容器化运行方式。

### 5.2 前端技术栈

| 类别 | 技术 |
| --- | --- |
| 语言 | TypeScript 5.6 |
| UI 框架 | React 18.3、React DOM 18.3 |
| 管理后台组件 | Ant Design 5.22、Ant Design Pro Components 2.8 |
| 图标 | `@ant-design/icons` 5.5 |
| 路由 | React Router DOM 6.28 |
| 构建工具 | Vite 6.0、`@vitejs/plugin-react` |
| 日期处理 | Day.js 1.11 |
| 单元测试 | Vitest 2.1、Testing Library、JSDOM |
| 端到端测试 | Playwright 1.54 |
| 代码检查 | ESLint 9、TypeScript ESLint |
| 包管理 | npm |

前端目录按功能划分为管理员页面、移动端页面、API 服务、路由、认证会话和公共样式。管理员端采用 Ant Design Pro 表格和表单组件；移动端采用独立路由和移动端优先布局。

### 5.3 后端技术栈

| 类别 | 技术 |
| --- | --- |
| 语言 | Java 17 |
| 应用框架 | Spring Boot 3.5.0 |
| Web/API | Spring Boot Starter Web |
| 安全 | Spring Security、无状态认证 |
| 数据访问 | Spring Data JPA、Hibernate |
| 参数校验 | Spring Boot Starter Validation、Jakarta Validation |
| 数据库 | PostgreSQL 16+ |
| 数据库迁移 | Flyway Core、Flyway PostgreSQL Database 支持 |
| Token | Auth0 `java-jwt` 4.4.0 |
| 密码哈希 | Spring Security BCryptPasswordEncoder |
| 构建工具 | Maven 3.9+ |
| 测试 | Spring Boot Test、Spring Security Test、JUnit、Testcontainers |

后端按认证、管理员账号、部门、被测评人员、测评用户、测评提交、结果统计和打印凭证等领域模块组织代码。

### 5.4 数据库技术

当前数据库迁移脚本创建以下核心表：

- `admin_user`：管理员账号、密码哈希、启用状态。
- `department`：部门名称、排序值。
- `evaluatee`：被测评人员、部门归属、启用状态。
- `evaluator_user`：测评用户账号、明文密码、部门归属、提交状态。
- `evaluation_record`：测评用户对被测评人员的等级评价、备注字段和提交时间。

数据库使用唯一约束、外键、检查约束和查询索引保障数据一致性。例如用户名和部门名称唯一，评价等级限定在四个固定枚举值内，评价记录按测评用户和被测评人员建立唯一约束。

## 6. 认证、安全与权限

- 管理员和测评用户分别使用独立登录接口。
- 登录成功后由后端签发 JWT，令牌包含用户 ID、角色、用户名、签发时间和过期时间。
- 前端将令牌保存在浏览器 `localStorage`，API 请求通过 `Authorization: Bearer <token>` 发送。
- 后端采用无状态 Session 策略，不依赖服务端会话。
- 管理员密码使用 BCrypt 哈希保存。
- 测评用户密码按当前业务要求以明文保存，用于管理员查看、重置和打印账号凭证；该设计属于当前版本的业务约束，应在生产环境做好数据库访问控制和传输加密。
- 生产环境建议启用 HTTPS，并替换默认 JWT 密钥、数据库连接信息和初始管理员配置。

## 7. 部署与运行

### 7.1 运行环境

- Java 17
- Maven 3.9 或更高版本
- Node.js 20 或更高版本
- npm 10 或更高版本
- PostgreSQL 16 或更高版本
- Docker（用于本地或测试环境运行 PostgreSQL）

### 7.2 服务组成

典型部署由以下部分组成：

1. Spring Boot 后端服务，默认监听 `8080` 端口。
2. 前端静态站点，可由 Vite 构建后交给 Nginx 托管，也可由后端统一托管。
3. PostgreSQL 数据库，数据库名默认为 `smart_eval`。

### 7.3 本地启动方式

```bash
docker compose up -d postgres

cd backend
mvn spring-boot:run

cd frontend
npm install
npm run dev
```

前端开发服务器默认监听 `5173` 端口，并将 `/api` 请求代理到 `http://localhost:8080`。

### 7.4 初始管理员

系统默认关闭管理员自动初始化。首次部署空数据库时，可通过环境变量临时启用初始化管理员；创建成功后应关闭该开关，并及时修改生产密码。

```bash
APP_BOOTSTRAP_ADMIN_ENABLED=true \
APP_BOOTSTRAP_ADMIN_USERNAME=admin \
APP_BOOTSTRAP_ADMIN_PASSWORD=<生产环境密码> \
mvn spring-boot:run
```

## 8. 测试与质量保障

- 后端包含认证、安全配置、数据库迁移、领域服务、控制器和端到端流程测试。
- 后端支持使用 Testcontainers 启动 PostgreSQL 进行集成测试。
- 前端包含路由、结果页面、移动端流程、管理员页面、登录服务和全局布局测试。
- Playwright 当前提供管理员登录页和移动端登录页的路由渲染检查。
- 可执行的常用检查命令：

```bash
cd backend && mvn test
cd frontend && npm run test
cd frontend && npm run lint
cd frontend && npm run build
cd frontend && npm exec playwright test
```

## 9. 当前版本边界

以下能力不属于当前版本已实现范围：

- 测评批次或多场测评活动管理。
- Excel 或其他格式的数据导入。
- Excel 导出和结果文件导出。
- 图表化统计看板。
- 测评用户自行修改密码。
- 可配置的测评指标表或自定义等级。
- 匿名评价。
- 复杂的组织层级和跨部门测评配置。

## 10. 交付建议

正式上线前建议由客户与实施方共同确认以下事项：

- 生产数据库地址、账号、备份策略和访问白名单。
- JWT 密钥、管理员初始密码及密钥轮换策略。
- HTTPS 证书和移动端访问地址。
- 测评用户明文凭证的保管、打印、发放和回收流程。
- 测评活动开始/结束时间及数据归档要求；当前版本未内置批次和时间窗口控制。
- 上线前使用真实业务数据执行一次完整的管理员配置、账号打印、移动端测评和结果核对流程。
