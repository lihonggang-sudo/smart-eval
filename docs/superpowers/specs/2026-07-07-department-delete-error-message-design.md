# 部门删除失败提示设计

## 目标

管理员删除部门时，如果后端因为部门存在关联数据而拒绝删除，前端需要展示后端响应中的 `message`，例如：

`部门下存在关联数据，不能删除`

## 范围

本次只调整后台部门管理页面的删除操作。新增部门和编辑部门流程保持不变。

## 当前行为

`frontend/src/request.ts` 已经会把失败的 API 响应转换成 `Error`，并使用后端返回的 `message` 作为错误信息。部门删除确认回调当前直接 `await deleteDepartment(record.id)`，没有捕获异常，所以后端业务提示没有展示给用户。

## 方案

在部门删除确认回调中增加 `try/catch`。

删除成功时：

- 保持现有成功提示：`部门已删除`
- 刷新部门列表

删除失败时：

- 如果捕获到的是 `Error`，展示 `error.message`
- 如果捕获到的不是 `Error`，展示兜底提示：`删除部门失败，请稍后重试`
- 不刷新部门列表

## 备选方案

1. 在 `Departments.tsx` 中本地处理删除失败。
   这是推荐方案，因为请求层已经保留了后端 `message`，且本次需求只涉及部门删除。

2. 在 `request.ts` 中增加全局 API 错误提示。
   这可以减少后续重复处理，但会改变整个前端的错误提示行为，可能导致现有页面出现重复或非预期提示。

3. 同时调整部门新增、编辑、删除的失败处理。
   这后续可能有价值，但会扩大本次任务范围，超出当前反馈的问题。

## 测试

新增或更新前端后台页面测试：模拟 `deleteDepartment` 抛出 `new Error('部门下存在关联数据，不能删除')`，触发删除确认，并断言 `message.error` 接收到这段完整文本。

实现后运行相关前端测试。
